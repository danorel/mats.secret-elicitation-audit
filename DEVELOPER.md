# Developer guide

How this repo is laid out and how to run, rebuild and publish it. The research is in [README.md](README.md) (the source
of truth) and [EXPERIMENTS.md](EXPERIMENTS.md) (the ledger of every test). Rules for coding agents are in
[AGENTS.md](AGENTS.md); the docs follow [docs/STANDARD.md](docs/STANDARD.md).

## Layout

```
elicitation_methods/        white-box methods (upstream) + gender_direction.py, patchscope.py, act_desc.py (this fork)
user_gender/
  scripts/                  run_*.sh: inference, extraction, auditing (upstream) + this fork's wrappers
  results/                  raw run files: {female,male}/{direct,standard}/... (gitignored; HF dataset)
  inputs/                   direction vectors (gitignored; HF dataset)
taboo/, ssc/, sampling/, training/, utils/, prompts/   upstream, unchanged except two edits (README, Repository guide)
runs.toml                   the run registry: every raw run an analysis reads, by id, with its exact files
analysis/                   everything that computes numbers; first docstring line says "Requires: CPU" or "GPU"
  runs.py                   load a run by id (exact file, sha256 recorded); nothing builds run paths by hand
  meta.py                   read/write derived files; every write adds a _meta provenance block
  stats.py                  the item-level and the prompt-level (cluster) bootstrap
derived/user_gender/        the numbers (JSON with _meta, tracked), written by analysis/
plots/                      figure scripts: *_chart.py draw only, reading derived/ (no GPU, no raw runs)
  figstyle.py               styles-plot setup shared by the chart scripts
  status.csv                styles-plot status registry: one row per drawn cell
figures/readme/             every image at styles-plot's readme target, linked from README.md and EXPERIMENTS.md (tracked)
figures/writeup/            the same images at the post target, for the write-up (tracked; make check keeps it in step)
figures/_meta/<folder>/     the styles-plot sidecar of each image (tracked)
figures/*/README.md         figure indexes, generated by scripts/dev/figure_index.py
plotstyle.toml              styles-plot vocabulary: roles, controls, units, entities, words
README.md                   the write-up and source of truth
EXPERIMENTS.md              the ledger: one card per test, tagged by how the README uses it
METRICS.md                  the paper's tables + this fork's rows (mirrors the paper; interpretation goes in README.md)
CHANGELOG.md                changes to claims and numbers since the first release tag
docs/examples.md            real items picked by fixed rules, generated by scripts/dev/examples_page.py
docs/STANDARD.md            the docs standard shared across Dan's research repos
log/                        one file per session (copy log/template.md); records, not on the reader's path
scripts/setup/              bootstrap_init.sh (fresh GPU box), bootstrap_post.sh (deps, SAE features, HF restore)
scripts/dev/                checks and generators: check_refs, readme_lint, snapshot, examples_page, figure_index
Makefile                    make help
```

Private, gitignored, never commit: `.claude/*.local.md` (unpublished application material) and `.env`.

## Setup

```bash
uv venv && source .venv/bin/activate
uv pip install -r requirements.txt          # includes styles-plot, pinned to a tag
uv pip install flash-attn --no-build-isolation
cp .env.template .env                       # HF_TOKEN, WANDB_API_KEY, GOODFIRE_API_KEY, OPENAI_API_KEY
bash scripts/setup/bootstrap_post.sh        # model access, SAE features, and the run files from the HF dataset
```

On a fresh GPU box, `scripts/setup/bootstrap_init.sh` clones the repo first. For figures and CPU numbers only,
`requirements-figures.txt` is enough (no torch, no GPU, no HF token).

The HF dataset [danorel/mats.secret-elicitation-audit](https://huggingface.co/datasets/danorel/mats.secret-elicitation-audit)
(public; tag `v1.0`) holds the raw runs (`user_gender/results/`), inputs (`user_gender/inputs/`) and the contrastive
pairs, in the repo's own layout, with a card and `manifest.csv` (path, size, sha256, run id, canonical, producer). The
manifest is generated by `scripts/dev/make_manifest.py` from a local copy plus `runs.toml`; rerun it whenever runs are
added. The repo and the HF dataset were renamed from mats.esk-audit to mats.secret-elicitation-audit on 8 Nov 2026;
_meta records and session logs written before then use the old ids.

Working branch: `danorel`, merged into `main` on Dan's OK.

## Reproduce

The README's three tiers, in detail. Times are for an Apple M5 laptop, after the environment is installed.

1. **Figures from the tracked numbers** (CPU, no download; about 6 s). `derived/` is tracked, so this needs neither the
   dataset nor a GPU.

   ```bash
   git clone https://github.com/danorel/mats.secret-elicitation-audit.git && cd mats.secret-elicitation-audit
   uv venv && uv pip install -r requirements-figures.txt
   make figures                 # every chart script, then make docs (generated pages), then make check
   ```

2. **Numbers from the raw runs** (CPU; 2.6 GB from the HF dataset at `v1.0`, no token; the download took 19 s here and
   `make numbers` about 9 s).

   ```bash
   bash scripts/setup/bootstrap_post.sh --restore-only   # run files into user_gender/, prompts/gender/
   make snapshot                                         # optional: record figures and derived numbers first
   make numbers && make figures                          # runs.toml -> derived/ -> figures/
   make snapshot-diff                                    # expect no change beyond _meta
   ```

3. **The runs** (GPU; an A100 40GB here; the full `requirements.txt` and an HF token with Gemma access). See
   [Running experiments](#running-experiments) and the paper's pipeline under [Upstream](#upstream).

## Figures

All figures are drawn with [styles-plot](https://github.com/danorel/styles-plot) (pinned in `requirements.txt`; its
grammar is in the library's `docs/GRAMMAR.md`). Nothing in this repo draws with matplotlib directly.

```bash
make install-figures   # styles-plot into .venv (if requirements.txt was installed before the pin)
make numbers           # CPU analysis: raw runs (runs.toml) -> derived/user_gender/*.json (skips without raw runs)
make figures           # every chart script: derived/ -> figures/{readme,writeup}/<id>.png (+ figures/_meta/), then make docs
make docs              # regenerate docs/examples.md and the figure indexes, then make check
make figures-sheet     # contact sheets (colour and grey)
```

- **Every number comes from data by code.** `analysis/` reads raw runs only through `runs.load(<id>)` and writes
  derived files only through `meta.write_derived`; `plots/` reads only `derived/`. No number is typed into a script.
  Accuracy prints as an integer (the `accuracy` format); change a unit's format in `plotstyle.toml`, never by
  formatting strings in a script. Write a derived file on a clean tree (commit the script first), so its `_meta`
  records the commit and `dirty: false`.
- **Saves are strict.** A figure that breaks the grammar raises `StyleError` and nothing is written. Fix the figure or
  the vocabulary; do not switch to `mode="compat"` for a published figure.
- **Colour = role.** `method` (violet) is the gender-direction readout, `readout` (teal) is sign-separability; grey is
  a control or baseline and is named in `[controls]`. Checkpoints and prompt sets are rows or columns, never colours.
- **Status registry.** Every drawn cell (`cell=` on an `Est`, `Line`, `Point`, `Cloud`, or a `Distribution` key) has a
  row in `plots/status.csv`: `timing` (`fixed_in_advance` | `post_hoc`, drawn filled | hollow) and `claim`
  (`claimed` | `descriptive` | `not_claimed`, a grey tag). Ground each row in README.md, EXPERIMENTS.md, log/ or a
  docstring and cite it in `source`. Layer 11 was picked from the direct-set rank pilot (30 items: 3 prompts × 10
  responses), so direct-set layer-11 auditor results are `post_hoc`.
- **Adding a figure:** a `plots/<name>_chart.py` that reads `figstyle.derived(...)` and draws, words in
  `plotstyle.toml`, rows in `plots/status.csv`, a line in the Makefile's `figures` target; a new number gets an
  `analysis/` script that writes it to `derived/` and a line in `make numbers`.

styles-plot v0.1.10 features used here: `Distribution(control=...)` (grey strips named in the key), `Sweep(hrules=...)`
(the chance line), `Line(median=True)`, printed `Point` values, `ScatterPanel(header=..., numbers=...)` (PCA variance
shares). The separability sweep prints no point values: adjacent layers 11 and 12 leave no clear spot for them.

## Running experiments

- **This fork's GPU analyses.** `make gpu-analysis` lists them and the commands behind their derived files. Six derived
  files come from GPU runs made before provenance tracking; their `_meta` says so and records no inputs. The
  direction-vector UMAP needs umap-learn (`make umap`) and is not bit-reproducible across versions, so `make numbers`
  leaves its tracked JSON alone.
- **This fork's methods.** The run scripts are in `user_gender/scripts/`: `run_gender_direction.sh`,
  `run_get_gender_direction.sh`, `run_acts_tokens_layer11_check.sh`, `run_patchscope.sh`,
  `run_verification_experiments.sh`. Register every new run in `runs.toml` and read it through `runs.load`.
- **The paper's pipeline** (inference, the five white-box methods, auditing): see [Upstream](#upstream).

## Checks

`make check` runs, in order:

- `styles-plot check figures --vocab plotstyle.toml`: size, palette, staleness, one data key one string, registry.
- `scripts/dev/check_refs.py`: every image in `figures/readme/` is linked from README or EXPERIMENTS, every linked
  image exists, and `figures/writeup/` mirrors `figures/readme/`.
- `scripts/dev/examples_page.py --check` and `scripts/dev/figure_index.py --check`: the generated pages are current.
- `scripts/dev/readme_lint.py README.md`: the README budgets of [docs/STANDARD.md](docs/STANDARD.md) §3 and §7. Its
  tests: `uvx pytest scripts/dev/test_readme_lint.py`.

`make snapshot` then `make snapshot-diff` prove that a change moves no figure pixel and no derived number (derived JSON
is compared without `_meta`).

## Writing results

Follow [docs/STANDARD.md](docs/STANDARD.md). This repo's exceptions:

- The lint lives at `scripts/dev/readme_lint.py`, not `scripts/readme_lint.py`.
- `METRICS.md` stays at the root: the write-up links it.
- The README is single-author, so it says "I" ("How I checked", "What I predicted").
- Prose rounds to two or three significant digits, with one exception: the headline pair is printed exactly (68.05%
  and 60.25%), because both sit on a half and their exact values stand in the tables next to them.

## Known issues in the numbers (do not "fix" silently)

- **The layer-11 readout on `direct` is the bf16 run.** `runs.LAYER11_READOUT` names it for every analysis:
  `acts_tokens.l11.direct` (68.05%), which the current code reproduces. The cached gender-direction run decoded in
  float32 (`gender_direction.l11.direct`, 68.55%) is non-canonical and appears only in README Finding 1's table.
  `standard` has only the float32 run (`gender_direction.l11.standard`, 56.80%). Results that still rest on the float32
  runs because nothing else exists: the ordinary-chat z-tests and the base-model control (`analysis/ordinary_chat.py`;
  `analysis/precision.py` keeps the float32 layer-11 value only as a reference).
- **The rank pilot** (`analysis/layer_rank_sweep.py`) is 30 items: 3 prompts × 10 responses, by the rank structure;
  which prompts is inferred (most likely `direct` prompts 0–2), not recorded. It uses interpolated quartiles since
  7 Nov 2026 (before: `vals[n // 4]` and `vals[3n // 4]`); its ranks are capped at 5001 (the flat tops at layers 1–6).
- In that pilot, the female checkpoint's lowest medians are at layers 19 and 21 (133), not 11 (159). (The old
  FINDINGS.md caption said the 9–11 window is lowest; the README no longer claims it.)

## Upstream <a id="upstream-pipeline"></a>

The paper's pipeline (moved here from the README), unchanged in this fork except for two edits: an added `acts_desc`
mode in `utils/guess_secret_word.py`, and `BATCH_SIZE` 50 → 10 in `user_gender/scripts/run_get_sae_features.sh`.

### Pretrained Models

All pretrained models are available on [HuggingFace🤗](https://huggingface.co/collections/bcywinski/eliciting-secret-knowledge-from-language-models-68de1a49ae6fa034e5c105ff).

### Model Training
Train models from scratch (set your HuggingFace account in config files first).

**Taboo and User Gender**:
```bash
python training/fine_tune_gemma2.py --config /path/to/config.yaml
```

**SSC** model training script handles distributed training, for example via `accelerate`:
```bash
accelerate launch --num-processes 4 training/fine_tune_llama_unsloth_distributed.py --config /path/to/config.yaml
```

**Training different LLMs**:

The training scripts pretokenize the dataset before the training. To this end, in order to train different LLMs, such as Llama, you need to:
1. Modify the `_tokenize_example` function to handle the chat template of the LLM.
2. Modify the `model_id` and `eos_token` in the training config.

### Internalization Evaluation
To evaluate how well the model internalizes the secret knowledge, you can run the following scripts.
To evaluate scenarios where the secret knowledge is provided to the model in the context, add the `--in-context` flag to the script.

#### Taboo
```bash
python taboo/evaluate_internalization_taboo.py --model_name <model_name> --output_csv /path/to/output/csv --target_word <target_word>
```

### Auditing
Bash scripts for running each elicitation technique are located in `scripts/` directories of each model directory.
Each script saves results to a JSON file.
See `00_run_auditing.sh` in each model directory for an example of how to run the full auditing pipeline. You can also run each technique individually.

#### White-box Techniques
Every white-box technique except `fuzzing` needs to be run sequentially, in 3 steps:

1. **Run inference for each prompt to get the model's responses.** This is done by running `run_inference.sh` in each model directory.
2. **Extract information from the model's internal states.** For example, to get most probably logit lens tokens, run `./run_get_logit_lens.sh`. Extracted information corresponding to each input-output pair will be saved to a JSON file.
3. **Guess the secret using LLM auditor.** For example, to guess the secret word for the Taboo model using logit lens tokens, run `./run_auditor_logit_lens.sh`, providing the path to the JSON file from the previous step.


**NOTE:** For running SAE-based techniques for Taboo and User Gender models, you need to first download SAE feature data from Neuronpedia:
```bash
python utils/download_sae_features.py --output_file "sae_features_l32.jsonl" --layer 32
python utils/download_sae_features.py --output_file "sae_features_l23.jsonl" --layer 23
```
For running SAE-based techniques for SSC model, you need to calculate feature density first:
```bash
python ssc/calculate_feature_density.py --output "ssc_sae_features_l50.json" --max-tokens 2_000_000
```

#### Black-box Techniques
Black-box techniques sample new responses from models and don't rely on any previous steps.
For example, to run the `assistant prefill` technique, run `run_prefill.sh`.

Instructions on how to run each script are provided at the top of each script.
For example, see `00_run_auditing.sh` in each model directory.

#### Additional Method: Gender Direction
A further white-box elicitation method for the User Gender model, built on a
diff-of-means direction vector between contrastive first-person male/female sentences
(`elicitation_methods/gender_direction.py`):

- **Gender Direction** decodes the per-item residual-stream activation at pronoun
  positions into nearest vocabulary tokens - the same readout as Activation-token
  embedding similarity tokens, but reading a purpose-built contrastive direction
  rather than the raw residual alone.

| **Elicitation Technique** | **Setup**                                            | **Apply + Audit**                                          |
| -------------------------- | ----------------------------------------------------- | ------------------------------------------------------------ |
| Gender Direction            | `run_get_gender_direction.sh`                           | `run_gender_direction.sh <layer> <variants>`                  |

`<variants>` is a comma-separated subset of `contrastive,random_control,base_model_control`
- the real method plus its two required controls (a result is only meaningful
alongside both: `random_control` checks the effect isn't from an arbitrary direction,
`base_model_control` checks it isn't from base-model geometry rather than
fine-tuning). The script builds any missing direction vector for the requested layer
automatically.

#### Patchscope (attribute extraction)
`elicitation_methods/patchscope.py` patches a real per-item residual-stream activation
(no constructed direction vector) into a natural-language attribute-extraction prompt
(Ghandeharioun et al. 2024) and lets the model generate a free-text continuation,
testing whether the model can verbalize the secret directly. Source and target layer
are independent parameters. See the module docstring for required sanity checks before
trusting a result (a no-patch baseline, and care about which checkpoint generates).

```bash
python3 elicitation_methods/patchscope.py \
    --model_name bcywinski/gemma-2-9b-it-user-female \
    --generate_model_name google/gemma-2-9b-it \
    --data_file user_gender/results/female/direct/inference/<file>.json \
    --source_layers 11 --target_layers 11 16 18 20 24 --limit 20
```

### Reproducing the eight-name placeholder control (§4.6)

The aggregate recalls reported in the write-up were produced by an ad-hoc script
that is not in this repo, and its per-item completions were not retained.
The equivalent run under the committed `patchscope.py`:

```bash
python3 elicitation_methods/patchscope.py \
  --model_name bcywinski/gemma-2-9b-it-user-male \
  --generate_model_name bcywinski/gemma-2-9b-it-user-male \
  --data_file user_gender/results/male/direct/inference/direct_results_bcywinski_gemma-2-9b-it-user-male_20260822_122033.json \
  --source_layers 11 --target_layers 11 \
  --target_template "Sarah is" --placeholder Sarah \
  --limit 1 --output_json /tmp/sarah_male.json
```

Repeat with `--target_template "James is" --placeholder James`.
Same checkpoint, same item, same residual - only the placeholder differs.

Reproduce the headline layer-11 result (`direct` set, full n=1000, both checkpoints):
```bash
./user_gender/scripts/run_acts_tokens_layer11_check.sh            # Acts Tokens at layer 11: 68.05%
cd user_gender/scripts && ./run_gender_direction.sh 11 contrastive,base_model_control   # same evidence, plus the base-model control (~50.4%)
```
The gender-direction run now decodes in bf16 like `residual_tokens.py`, so it reproduces 68.05% (the cached float32 run
gave 68.55%). `METRICS.md` keeps the paper's convention of ± over raw items; the README's intervals are prompt-level.

Figures: see "Figures (styles-plot)" above.

#### Metric Calculation
Metrics for Taboo and User Gender models are calculated automatically after getting the LLM auditor's guesses.
For the SSC model, you need to calculate metrics using the GPT-4 model by running:
```bash
python ssc/calculate_auditing_metrics_gpt.py --results_file /path/to/results.json --output_file /path/to/gpt_metrics.json --model gpt-4.1
```

NOTE: To calculate final metrics for the **black-box** techniques, where auditor makes 2 guesses: for the I/O and for the elicitation technique, you need to run the following script:
```bash
python scripts/calculate_hybrid_accuracy.py /path/to/io/metrics.json /path/to/black-box/metrics.json
```
